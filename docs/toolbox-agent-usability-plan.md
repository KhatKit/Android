# Toolbox Agent 易用性提升规划

状态：待实施。范围：KhatKit Android 客户端与 KodeHeapServer。本文定义产品行为和验收，不表示功能已经落地。

## 1. 产品目标

KhatKit 以工具箱为主要目的：用户先找到能完成事情的能力，可以直接运行，也可以交给 agent 组合执行；完成后能找到、分享和复用结果。

第一期打通：**找到工具 → 准备运行 → 看懂进度 → 拿到结果 → 再次使用**。

- 明确输入输出的工具支持直接运行，不强制先配置助手或开启对话；需要推理时才检查模型。
- 用户也可以输入需求、附件或链接，让 agent 选择工具。执行前说明所选助手、执行范围及材料去向。
- 安装、配置、启用与可运行分别展示；缺什么就给出补齐入口。
- 卡片、Skill、MCP、工作流和工作区继续作为执行基础；首页按用途组织，技术类型放在详情和筛选。
- MD3 与 Miuix 的入口、功能、状态与无障碍能力一致，复用现有 Kedge 组件。

第一期聚焦使用闭环，不扩充推理引擎、角色玩法或多设备架构。

## 3. 信息架构

主要目的地为 **工具箱、任务、我的**。默认进入工具箱；升级用户保留会话直达入口，可选择默认打开工具箱或上次会话。

| 目的地 | 首屏内容 | 主要操作 |
|---|---|---|
| 工具箱 | 搜索、需求输入、收藏、最近使用、场景分类 | 直接运行、交给 agent、添加材料、发现更多 |
| 任务 | 进行中、需要处理、最近完成 | 补配置、审批、停止、查看结果、再次运行 |
| 我的 | 已安装工具、助手、工作区、连接与设置 | 管理能力、运行环境与数据 |

搜索与需求输入分别标明用途。搜索不发起模型请求，“交给 agent”才启动推理。推荐区优先展示已安装、适配当前设备的工具；没有工具时提供可操作的安装入口。

工具条目至少展示：动作名称、一句说明、输入、输出、运行方式和就绪状态。例如“压缩图片 / 减小体积并保留原图 / 图片 → 图片 / 直接运行”。详情补充示例、权限、联网/模型要求、范围、版本、作者、来源和最近运行。

无表单或明确执行契约的扩展只提供 agent 入口；提供商插件等基础设施进入“连接与配置”，不显示无效的运行按钮。

### 状态模型

| 维度 | 状态 |
|---|---|
| 安装 | 未安装、安装中、已安装、更新可用、安装失败 |
| 配置 | 无需配置、需要配置、已配置 |
| 范围 | 当前助手已启用、其他助手已启用、尚未启用 |
| 健康 | 未检查、检查中、可用、连接失败、不兼容、已撤销 |

可运行状态由以上维度、本次输入和运行方式计算。无模型工具不受模型配置影响；直运行不要求绑定助手。健康检查显示时间和重试入口，不把一次失败当作永久不可用。

## 4. 核心流程与验收

### A. 第一次完成任务

首次启动先选任务，如图片处理、链接整理或文件处理，再展示工具与实际要求。允许跳过；仅在任务需要时补模型、权限或依赖。取消配置保留输入，允许改选要求更少的工具。

验收：新用户能完成一个真实、无需模型的工具任务；随后使用模型任务时只补模型配置，不重复引导。目标为至少 5 位首次使用者中 4 位在 3 分钟内完成首个任务；安装、下载等待时间单独报告。

### B. 搜索并直接运行

搜索覆盖名称、用途、别名与输入类型，优先展示已安装且适配的结果。无结果提供市场搜索和可编辑需求入口，不自动安装。

工具输入表单提供默认值、示例、必填标记、数量与大小限制，运行前完成校验。优先复用已有 schema 表单；缺少契约先补元数据，不能猜参数。

验收：收藏工具到输入表单最多 2 次点击；无模型工具零模型调用；校验失败、返回或补配置不丢草稿，可主动清空。

### C. 从分享进入 agent

接收文本、链接及系统授权文件 URI，按 MIME 和实际读取能力推荐动作。先预览材料和动作，确认后执行；外部分享不隐式发送给模型。

复杂任务用简短摘要说明目标、能力与结果位置，只询问阻塞执行的关键项。补齐配置后回到原任务，不要求重新分享。

验收：文本、图片、多文件分别完成“分享 → 选动作 → 执行”；URI 失效提示重选具体文件；模型调用前能看见哪些材料将被发送。

### D. 看懂执行与失败

任务摘要展示名称、当前动作、已耗时、待处理项、停止入口和来源会话。工具步骤复用现有渲染器，原始参数与响应按需展开。没有可靠总量就用不定进度，不制造百分比。

任务状态为 `queued → preparing → running → succeeded / failed / cancelled / interrupted`；准备或运行阶段可进入 `waiting_user`，处理后回到原阶段。终态再次执行创建新记录，以 `parentRunId` 关联。

关闭页面不等于停止；只有运行器支持后台执行时才承诺后台继续。重启后检查实际运行状态，不能确认继续运行的任务标为中断。

| 失败 | 下一步 |
|---|---|
| 缺配置、权限、依赖 | 点名缺项，补齐后回到原任务 |
| 网络或限流 | 说明是否可重试及等待时间，保留输入 |
| 模型或工具不兼容 | 提供可用替代项，确认后切换 |
| 输入或执行错误 | 定位字段或步骤，编辑后创建新运行 |
| 文件丢失、授权失效 | 点名文件，重选输入或重新生成 |

发送、购买、删除、覆盖等审批显示目标、数量与影响，保留原审批边界。主按钮使用文本与至少 48dp 触控区域。重试检查步骤可重复性；不确定是否已完成的副作用步骤要求确认，不从头自动重放。

验收：切后台、返回页面、网络断开、拒绝审批、主动停止、进程重启六类情况均有明确状态，不出现终态持续转圈。

### E. 拿到结果并复用

结果页优先展示文件名、类型、大小、预览、打开、分享和保存位置；文本可复制，链接可打开。产物关联任务、会话和工具版本，不仅显示 Toast。

再次运行复制普通参数并允许编辑；密钥、一次性授权和过期 URI 不进入模板。续聊与重跑工具使用不同按钮。

验收：重启后能找到上次结果并打开仍存在的文件；文件移除时给出解释。删除任务默认只删记录，删除文件另行明确选择。下载仍由现有下载中心负责。

### U10：删除旧 `tool.http*`（待实施，用户已确定）

决策：删除 `tool.httpGet`、`tool.httpPost`、`tool.httpMultipart`，统一使用 `net.get`、`net.post`、`net.multipart`。不再采用“保留兼容并标记废弃”的方案。本次仅记录待办，代码尚未删除；此项是对旧卡片的破坏性 API 变更。

实施范围与顺序：

1. 盘点客户端与 KodeHeapServer 中的内置卡片、脚本、示例、生成模板、提示词、校验规则和测试，迁移所有旧网络调用；同步声明 `net` bridge 与 `network.allow`。已发布或用户自建旧卡片需明确提示更新，不能承诺继续兼容。
2. 先补齐迁移所需行为：核对 POST 请求体与 Content-Type；迁移 multipart 文件上传、图片响应落盘及返回路径。当前 `net.multipart` 的 `saveBinary` 尚未实现旧接口的图片保存行为，不可只替换方法名。文件读写接入相应授权范围。
3. 从 `ToolBridge` 接口及 `AndroidToolBridge` 实现删除三个旧方法，清理 `legacyNet` 与仅由旧网络方法使用的辅助代码、导入。保留其他 `tool.*` 能力，本项不扩展为整个 tool bridge 删除。
4. 更新脚本 API 参考、Lua 开发指南、Zenneko 说明和示例；同步检查服务端分发内容，避免客户端升级后仍下发旧脚本。变更说明明确旧入口已移除和迁移方式。

现状线索：[AndroidToolBridge.kt](../khatkit/src/main/java/heizige/kk/khatkit/bridge/impl/AndroidToolBridge.kt) 中旧 GET/POST 使用未传白名单的 `legacyNet`；[AndroidNetBridge.kt](../khatkit/src/main/java/heizige/kk/khatkit/bridge/impl/AndroidNetBridge.kt) 默认白名单为空。此次直接迁移并删除旧入口，不另建旧接口兼容层。

验收：三个旧方法不再定义或暴露；两仓可执行脚本、模板与示例不再调用旧方法（历史记录、移除说明及负向测试可保留名称）；GET、POST、multipart 上传、图片响应保存与结果打开均通过真实用例；允许域名成功、未声明域名在发请求前拒绝；旧脚本失败时能定位已移除的方法并提示迁移。运行受影响测试及客户端构建，记录服务端卡片更新范围；实际部署另行确认。

## 6. 客户端落点与数据

- 工具箱位于 `app/feature/toolbox/`，任务与结果位于 `app/feature/tasks/`；确实由多个功能使用的代码才提升到 core。
- 复用卡片运行器、消息调用链、Skill/MCP 配置与下载管理。任务记录是统一索引，不新建平行执行器或重复安装数据库。
- 执行前持久化 `runId`、来源、工具稳定标识与版本、运行方式、必要输入引用和时间；记录状态、步骤、错误类别、会话/下载关联与产物。日志脱敏，正文按实际必要性保存。
- 同一次启动防重复；类型与来源共同参与工具标识，避免同名冲突。卸载、更新不破坏历史记录。
- 产物记录 URI、MIME、来源运行和访问状态，复用 FileProvider/系统选择器，不把私有路径当分享地址。
- 为旧用户设计迁移；历史对话可按需关联，不伪造过去运行状态或耗时。第一期不全量重建旧产物。
- 明确定义收藏、草稿、任务与产物的清理及备份范围；任务模板不导出密钥与临时授权。

## 7. KodeHeapServer 配合

服务端负责发现、分发和兼容说明；设备权限、密钥、助手范围与健康状态由客户端计算。首期任务和产物本地保存，不自动上传用户文件。

### P0：先保证已有工具稳定可用

源码审计发现两项分发风险，实施时先写复现和验收，再修复：

1. 原生依赖同版本上传会覆盖并重新签名：服务端应禁止同名同版本不同内容覆盖；相同内容重复上传可幂等。证据：[KhatKitDependencyStore.kt](../../../../IDEA/Project/KodeHeapServer/src/service/KhatKitDependencyStore.kt) 的 `install`。
2. 上传新依赖后按 name 更新卡片引用，可能改写旧卡片版本锁定：更新必须遵守具体版本与显式发布动作，不能隐式重定向历史版本。证据：[KhatKitHubService.kt](../../../../IDEA/Project/KodeHeapServer/src/service/KhatKitHubService.kt) 的依赖更新逻辑。

验收：相同版本不同哈希拒绝且旧包不变；重复同内容幂等；新版本发布后旧卡片仍解析原锁定版本，升级只影响明确选择升级的卡片。

### P1：使用说明契约

以下为建议字段，U8 开工时与现有 DTO/manifest 核对并冻结，避免双重 schema：

| 字段 | 语义 | 缺失回退 |
|---|---|---|
| `usage_schema_version` | 使用说明版本 | 旧条目逻辑 |
| `use_cases`、`search_aliases` | 用途、别名，沿用多语言回退 | 原名称/摘要 |
| `input_types`、`output_types` | MIME、文本、链接等 | 不承诺自动匹配 |
| `execution_modes` | `direct`、`agent` | 保留原入口，不猜直运行能力 |
| `requirements` | 模型、网络、依赖、客户端要求 | 检查已有 manifest |
| `examples` | 有上限的使用示例 | 不显示 |

当前 ImageToolbox 操作的细项参数仍以 JSON 字符串表达，需要优先为选中的真实工具补操作级输入契约，不能只靠工具总入口枚举生成表单。证据：[ImageToolboxCards.kt](../../../../IDEA/Project/KodeHeapServer/src/service/ImageToolboxCards.kt) 的工具参数定义。

服务端验证大小、枚举、版本与引用，不执行作者脚本生成说明。错误逐步提供稳定代码与可展示原因；下载完整性仍由客户端实际校验。

验收：旧客户端忽略新字段仍能列表/安装；无新字段的条目正常回退；未授权用户不能修改他人说明；撤销和不兼容在详情及运行前可识别。部署不属于本次文档交付。

## 8. 验收与度量

| 场景 | 通过标准 |
|---|---|
| 未配置模型，直运行本地工具 | 成功且无模型请求 |
| MCP 缺配置 | 缺项明确，补齐后回原输入；安装与连接状态分开 |
| 分享多图处理 | 预填材料、保留原图，新产物可分享 |
| Agent 多步骤任务 | 当前步骤可读，审批有目标，产物关联同一任务 |
| 断网、重试、停止、杀进程 | 状态真实，输入保留，副作用不静默重复 |
| 撤销、版本不兼容、文件丢失 | 原因与下一步明确，历史记录可看 |
| 大字体、TalkBack、两种 UI 风格 | 无操作缺失、关键错误截断或焦点陷阱 |

目标指标（尚未实测）：找到正确工具的耗时中位数 ≤15 秒；配置后返回并继续成功率 ≥80%；重启后 30 秒内找到产物的比例 ≥90%。首次任务成功率必须同时报告样本量。

先用本地调试记录和人工走查，不默认上报输入、文件内容、URL、密钥或原始日志。实施后记录命令、退出码、具体用例及设备，不能用源码存在代替体验验收。

切片运行受影响测试；客户端候选版本运行 `./gradlew assembleDebug test lint`；服务端运行 `./kotlin test`，失败与当时未修改基线逐项比较，不沿用历史失败数量。发布前完成小范围走查及场景矩阵。
